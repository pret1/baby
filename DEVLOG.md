## 2026-10-29 — Схема БД и первая миграция

**Сделано**
- `lib/db/schema.ts`: таблицы `children`, `feedings`, `weights`, `temperatures` по ТЗ.
- `drizzle.config.ts` читает `DATABASE_URL` из `.env.local` через `@next/env` (тот же механизм, что у Next.js).
- Миграция `drizzle/0000_init.sql`, скрипты `npm run db:generate | db:migrate | db:studio`.
- Проверено на локальном Postgres 17: миграция применяется, CHECK `before_feeding AND after_feeding` отклоняет запись.

**Решения**
- Все даты — `timestamptz`; `birth_date` тоже `timestamptz` (дата и время рождения), а не `date`.
- Перечисления (`feeding_type`, `breast_side`, `temperature_site`) — Postgres enum.
- Первичные ключи — `uuid` (`gen_random_uuid()`).
- Помимо обязательного CHECK для «до/после кормления» добавлены простые CHECK: `breast_side` заполнен только для типа `breast`, объём/длительность/вес > 0, температура 30–45 °C.
- `value_celsius` — `numeric(3,1)`, в коде читается как `number` (`mode: "number"`).
- `updated_at` обновляется автоматически при каждом UPDATE (`$onUpdate`) — этого достаточно для last-write-wins.

## 2026-10-29 — Подключение к Neon

**Сделано**
- `lib/db/index.ts`: пул `pg` + `drizzle-orm/node-postgres`, `attachDatabasePool` из `@vercel/functions`.
- `.env.example` с `DATABASE_URL`; `.env.local` в git не попадает.

**Решения**
- Пул создаётся лениво (`getDb()`), а не при импорте: сборка (`next build`) не требует `DATABASE_URL`.
- `connectionTimeoutMillis: 5s`, `query_timeout: 10s` — при недоступной БД запрос быстро падает, а не висит.
- `pool.on("error")` — Neon закрывает простаивающие соединения; без обработчика процесс бы падал.

## 2026-10-29 — Профиль ребёнка, возраст, каркас интерфейса

**Сделано**
- `/profile`: при первом запуске — форма «имя, дата и время рождения, вес»; дальше — редактирование и удаление профиля (со всеми записями, двухшаговое подтверждение).
- Без профиля любая страница перенаправляет на `/profile` (`requireChild()` в `lib/db/queries.ts`).
- Шапка с именем и возрастом: до 4 недель — дни, до ~3 месяцев — недели + дни, дальше — календарные месяцы (+ годы) и дни (`formatAge` в `lib/time.ts`).
- Нижняя навигация: Главная / Кормление / Вес / Температура.
- `app/error.tsx` — экран «Не удалось загрузить данные» с кнопкой «Повторить» (`retry()` заново запрашивает данные).

**Решения (паттерны, которые повторяются во всех разделах)**
- **Чтение**: серверный компонент внутри `<Suspense>` → `connection()` → запрос Drizzle → данные передаются в клиентский компонент.
- **Запись**: Server Actions в `lib/actions/*`. Сервер всегда валидирует вход через Zod. Ошибки БД ловятся в `runDb()` и возвращаются как `{ ok: false, error }`, после успеха — `refresh()` (обновляет данные текущей страницы).
- **Формы**: React Hook Form + `zodResolver`. Схема формы (`xxxFormSchema`, все поля — строки) преобразует значения и через `.pipe()` проверяется серверной схемой — правила описаны один раз в `lib/validation.ts`.
- **Время**: `datetime-local` → `Date` конвертируется в браузере (часовой пояс телефона), на сервер уходит уже абсолютный момент времени. Всё, что форматирует даты, рендерится только на клиенте через `useNow()` (иначе сервер в UTC и телефон дадут разный HTML).
- **Нет сети**: `callAction()` превращает упавший запрос к Server Action в понятную ошибку в форме; введённые данные не теряются.
- Без `confirm()` — удаление подтверждается второй кнопкой в интерфейсе.
